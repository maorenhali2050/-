# 创新模块边界与验收

## 1. 个性化图书推荐
输入：当前读者已归还或正在借阅的书目分类、可查询书目和有效借阅统计。
最小实现：按用户借阅分类次数排序，优先推荐偏好分类中有可借副本的图书，排除当前借阅和有效预约书目；按全站借阅次数与书目 ID 稳定排序，最多返回 5 本。不足时用热门可借书补齐，无历史完全使用热门结果。
输出：书目和推荐理由，例如“你常借文学类图书”。
边界：不修改库存、不替用户借书、不做机器学习训练。
入口：首页；前端 frontend/modules/recommendation/，后端 backend/src/modules/recommendation/。
验收：有历史、无历史、无库存、候选不足时均能给出合理结果或空状态。

## 2. 借阅逾期智能提醒
输入：未归还借阅记录、服务端当前时间。
最小实现：页面查询时显示逾期标记；每日定时任务为逾期记录生成站内提醒，同一借阅每天最多一条。
输出：我的借阅中的逾期天数、站内消息、管理员逾期列表。
边界：不自动扣费、不发送短信邮件、不参与预约分配。“智能”指自动判定和去重提醒。
入口：我的借阅；前端 frontend/modules/overdue-reminder/，后端 backend/src/modules/overdue-reminder/。
验收：到期前不提醒；超过到期时刻才逾期；任务重复执行不重复创建；归还后停止创建提醒。

## 3. 图书自动流转
定义：实物归还后，系统自动把该副本保留给同一书目的有效预约队首。
输入：管理员归还操作、waiting 预约队列、服务端时间。
规则：按 created_at、id 先后分配；队首变为 ready，副本变为 reserved，生成站内领取通知。默认保留 2 天（可配置），领取并确认借出后才建立新借阅记录。
无预约时副本变为 available。保留超时或取消时释放副本并继续尝试分配下一位；等待中的取消预约被跳过。
边界：不自动把预约当借出，不处理跨馆物流；副本库存写入统一通过借阅/流转业务服务完成。
入口：图书详情“预约”、个人预约列表、管理员领取/归还界面；前端 frontend/modules/circulation/，后端 backend/src/modules/circulation/。
验收：无人预约、多人排队、取消、超时、重复归还、并发归还/领取均不会重复分配；其他读者不能借走 reserved 副本。
