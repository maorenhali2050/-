# 开发顺序与毕业设计交付
以下均为待开发事项，不表示已经完成。

1. **确定需求与技术栈**：沿用学校要求，选一种前端、一种后端和一种数据库；确认读者/管理员角色及“自动流转”的预约分配定义。交付用例图、功能清单、ER 图。
2. **图书管理与登录**：完成数据库、样例书目、分类、实物副本、搜索、管理员维护和权限校验。验收读者不能调用管理接口。
3. **借阅与归还闭环**：管理员确认借出、我的借阅、到期日、归还与副本状态更新。验收同一副本不能同时借给两人，重复归还不重复释放。
4. **逾期提醒**：先做页面实时状态，再做每日站内消息任务和去重。用可控制的测试时间验证到期边界；保留任务日志。
5. **预约自动流转**：预约排队、归还分配、领取确认、取消和超时再分配。用两名读者与同一本书的一个副本演示完整过程。
6. **个性化推荐**：在借阅数据存在后完成类别规则与热门兜底，并显示推荐理由。对比有历史与新用户结果。
7. **验收与论文**：覆盖角色权限、异常输入、库存并发和三个创新点；收集真实运行截图、测试结果和局限说明。

## 最先做的一个开发任务
确定学校要求的技术栈，在 database/ 添加建表脚本及样例数据；
随后实现 GET /api/books，把静态入口替换为真实图书列表。
这一步完成后再开发借阅，避免一开始同时实现三个创新点。

## 论文对应章节
需求分析：角色、功能范围、业务流程。
系统设计：目录架构、ER 图、接口、预约状态转换。
系统实现：基础借还与三个创新模块的实际规则及界面。
系统测试：输入、预期、实际、结果与截图。
总结：只写已完成内容；规则推荐、站内提醒和预约分配的限制需如实说明。
